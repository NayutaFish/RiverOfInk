## 2. 总体美术方向

构筑 Icon 沿用项目已确认的 **飞白墨印图标风**：弱具象、强轮廓、强组内区分。它们是机制印记，不是技能 VFX 的缩略图。

统一语言：

- 墨黑、炭灰和宣纸白构成主要识别关系。
- 墨蓝只作为少量机制焦点或“最近构筑”的独立衬托，不承担 Icon 间的主要区分。
- 允许飞白、断笔、干湿变化和少量墨点，但纹理必须服务于主轮廓。
- Icon 本体不使用文字、数字、键位、稀有度边框或大面积发光。
- 透明背景，主体集中，四周保留安全边距。
- 同一组 Icon 不得全部套用“圆环 + 中央旋涡”模板；轮廓、负形和动势必须有明显差异。

详细风格基准见：

- [构筑 HUD Icon 美术风格方案](./build-icon-art-direction.md)
- [HUD Icon 总体方案](./README.md)

## 3. 目标画面构成

最终主 HUD 由以下层级组成：

```text
右下角紧凑纸张面板
┌──────────────────────────────┐
│   最近构筑（大）   上一构筑（小） │
│                       [ B ]     │
└──────────────────────────────┘
```

- 面板是横向、轻量的撕纸/宣纸形状，透明区域保留给游戏画面。
- 最近构筑是主要视觉焦点，位于左侧；上一构筑位于右侧，体量更小、视觉权重更弱。
- B 键提示位于面板底部居中，不要把 B 字符烘焙进底图；键位文字由技术层叠加，以便后续支持键位配置。
- 不制作标题、描述、属性数值或“最近获得”等文字。
- 不制作覆盖整个屏幕的暗色遮罩。面板外不能出现黑色矩形背景。

当前技术白盒的参考尺寸为 `500 × 250`（逻辑像素）：

| 区域 | 白盒参考尺寸 | 美术要求 |
| --- | ---: | --- |
| 整体面板 | 500 × 250 | 纸张主体和透明撕边覆盖该区域，不能裁掉边缘笔触 |
| 最近构筑槽位 | 约 300 × 178 | 主 Icon 在目标尺寸下保持清晰、集中 |
| 上一构筑槽位 | 约 142 × 154 | 可用稀疏墨迹或弱化衬托，但不烘焙 0.78 透明度 |
| B 键帽 | 约 36 × 36 | 只提供底图，文字由 C++/UMG 绘制 |

这些尺寸是技术对接基准，不要求美术文件本身按 500×250 制作；源图按下表的母版尺寸交付。

## 5. 三个测试构筑 Icon 的具体要求

### 5.1 TwoStageArc

表达“两段式弧形攻击/两阶段弧线”的机制，不需要画人物、武器或完整 VFX。

- 主轮廓：两道有先后关系的开放弧线，允许错位、断裂或前后叠置。
- 动势：两段弧线必须能读出不同阶段，不能合并成一个普通圆环。
- 负形：保留明显间隙或双层留白，让两段结构在缩小后仍分开。
- 墨迹：一段可偏重、一段可偏轻，但不能只靠颜色区分。
- 禁止：完整圆锥、完整圆盘、人物轮廓、文字和中心旋涡作为唯一主体。

### 5.2 TwinSlash

表达“双斩/双段切割”的机制。

- 主轮廓：两道清晰的斜向切割笔触，可交叉、平行错位或形成双刃结构。
- 动势：方向明确，优先体现切入和穿透感。
- 负形：两道斩痕之间必须有可辨认的空隙或错位关系。
- 墨迹：主体集中，外扩飞白少量即可。
- 禁止：使用圆环或旋涡作为主体，不能画成单一道大斜线。

### 5.3 Cooldown

表达“冷却缩短/循环加速”的机制，不画具体数字或计时器 UI。

- 主轮廓：断裂环、循环回路或重复弧段。
- 动势：通过缺口、回转方向或重复节奏表达循环和重新准备。
- 负形：缺口必须清楚，避免与 TwoStageArc 的双弧轮廓混淆。
- 墨迹：可使用较密的环形墨线，但中心应留出足够负形。
- 禁止：钟表数字、百分比、文字、单纯实心圆或与 TwoStageArc 相同的两段弧线。

## 6. 面板与键帽制作要求

### HUD 面板

- 使用宣纸、旧纸边、干墨和少量毛边，整体横向展开。
- 外轮廓可不规则，但不能因为撕边或飞溅破坏两个 Icon 的安全区。
- 主要底色偏宣纸白/灰白，黑灰墨迹用于边缘和层次。
- 墨蓝可以在最近构筑区域附近出现少量晕染，但不应成为整张面板的底色。
- 透明区域必须是真透明 alpha，不要用黑色、深灰色或棋盘格模拟透明。
- 不把两个 Icon、B 字符或槽位位置烘焙进面板；面板需要能被运行时独立复用。

### B 键帽底图

- 只制作键帽形状、边缘墨线和内部纸面/灰面。
- 不包含 `B`、任意其他字母、键位说明或鼠标图形。
- 在约 36×36 逻辑像素下仍能看出是一个独立按键底图。
- 不要使用强发光、霓虹蓝或高对比科技 UI 风格。

## 7. 导入与资产规范

- 所有素材必须为 RGBA 透明 PNG；透明区域不可带黑底、白底或棋盘格。
- Icon 保持 1:1 画布；面板保持 2:1 横向画布；键帽保持 1:1 画布。
- 主体四周保留约 8%～12% 安全边距，避免在 UMG 缩放时裁切飞白。
- UI 纹理使用项目现有 UI 纹理导入约定；至少确认 alpha 保留、Texture Group 为 UI、颜色空间与现有 HUD 纹理一致。
- 不擅自修改现有 `T_UI_Build_TwinSlash`、`T_UI_Build_Cooldown`、`T_UI_Build_Radius` 等奖励图标；新稿使用 `_Redrawn` 命名。
- 不删除 `TestIcons/Generated` 下的测试素材；它们仍可用于技术白盒回退验证。
- 资产导入后必须在 Content Browser 中确认对象路径与表格完全一致，避免仅存在源 PNG 但没有 UE 纹理资产。

## 8. 美术验收矩阵

### 单个素材

- [ ] PNG 和 `.uasset` 均存在，透明通道正确。
- [ ] 无文字、数字、键位、角色、面板外黑底或棋盘格。
- [ ] 缩小到 HUD 实际显示尺寸后，主轮廓仍清楚。
- [ ] 去掉墨蓝后，黑白轮廓和机制差异仍成立。
- [ ] 主体没有被飞白、墨点或撕边抢走。

### 三 Icon 组内

- [ ] TwoStageArc、TwinSlash、Cooldown 相邻显示时可以快速区分。
- [ ] TwoStageArc 读作双阶段开放弧，不读作圆锥或完整圆环。
- [ ] TwinSlash 读作两道斜切，不读作单道斩痕。
- [ ] Cooldown 读作断裂循环，不读作普通旋涡。
- [ ] 区分来自轮廓、负形和动势，不是来自蓝色或明暗。

### 组合画面

- [ ] 面板放入组件验收尺寸后，最近 Icon 在左侧较大，上一 Icon 在右侧较小。
- [ ] B 键帽位于面板底部居中，后续叠加动态文字后仍有足够留白。
- [ ] 面板外透明，放入游戏画面右下角后不出现矩形黑块或白块。
- [ ] 最近构筑墨蓝衬托（若制作）只强调最近槽位，不覆盖 Icon 主轮廓。
- [ ] 组合素材不会遮挡小地图、技能槽或主要战斗区域。
- [ ] 不出现详细信息标题、描述、属性数值或暂停界面元素。
