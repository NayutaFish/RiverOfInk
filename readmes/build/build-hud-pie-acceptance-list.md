# 战斗内构筑 HUD｜PIE 最终验收清单

> 状态：待 PIE 执行
>
> 适用分支：`codex/combat-build-hud-integration`
>
> 远程目标：`origin/codex/combat-build-hud`
>
> 测试地图：`/Game/Level/TwoStageArcVFXTest`

本清单用于战斗内常驻构筑 HUD 与 B 键详细构筑 HUD 的最终 PIE 验收。验收不能只看运行截图，必须同时对照以下两张基准图：

## 1. 必须同时对照的两张验收图

### 1.1 低保真原型图：确认结构和交互位置

[低保真原型图（无框箭头）](../../Content/RawContent/UI/BuildHUD/T_UI_BuildDetailsPanel_LowFidelityPrototype_WithScrollArrows_NoFrame.png)

重点确认：

- 左页五个分类行和组间分隔线的对应关系。
- 每个分类最多五个 Icon 槽位；`<` / `>` 位于槽位容器外，不占槽位。
- 箭头无框、无填充，始终留在左页对应分类行内。
- 当前选中 Icon 的位置、键盘/鼠标操作和窗口滚动方向。
- 右页预览、标题、说明和左页中缝之间的安全距离。

### 1.2 最终视觉验收图：确认美术层级和构图

[最终视觉验收图（无框箭头）](../../Content/RawContent/UI/BuildHUD/T_UI_BuildDetailsPanel_Separated_NoRightInkLabel_SimplifiedTexture_OpenLowerLeft_WithScrollArrows.png)

重点确认：

- 宣纸/飞白、边缘墨迹、挂饰、印章和组间分隔线均存在且保持独立层级。
- 左下角保留宣纸留白，不用额外墨迹或装饰填满。
- 选中态是中心填充的圆形墨蓝水痕，不是蓝色矩形。
- 黑、白 Icon 像素只来自 Build Icon；蓝墨层不含黑色或白色 Icon 形态。
- 面板外保持真透明，不出现矩形黑底、白底或棋盘格被烘焙进素材。
- `InkGrenade` 只表达投掷物式范围攻击、落点和区域覆盖，不出现炸弹、手雷或类似物体。

两张图的关系是：低保真图验收结构、槽位和交互；最终视觉图验收分层、纹理、颜色和构图。任一基准图不一致，都不能仅以“运行时能显示”为通过。

- [ ] 使用当前分支最新提交启动 UE 项目，地图为 `TwoStageArcVFXTest`。
- [ ] 关闭旧 PIE/Standalone 实例，确认没有残留的 Reward HUD 或 Details HUD。
- [ ] 确认 `T_UI_BuildDetailsPanel_PaperFeibai.png` 与同名 `.uasset` 均存在。
- [ ] 确认 `T_UI_BuildDetailsPanel_SelectedWash.png` 与同名 `.uasset` 均存在。
- [ ] 确认当前 `build-list.md` 中的 BuildId、类别、排序和 IconKey 是本次唯一对照清单。
- [ ] 若需重新编译 C++，先关闭 `UnrealEditor.exe` 和 Live Coding，再使用项目指定的 bundled `Build.bat`；不得并行启动第二个 UBT。

## 3. 构筑数据准备

启动 PIE 后，在 UE 控制台逐条执行以下命令验证构筑获取和 HUD 刷新。每条命令执行后等待上一条奖励反馈结束：

```text
DebugSelectSpecificReward TwoStageArc 1
DebugSelectSpecificReward Cooldown 1
```

用于补充 Q 分类测试的合法标识符包括：

```text
AddProjectile
InkGrenade
ExtraExplosion
Q.CooldownDown
ProjectileHoming
```

用于补充 E 分类测试的合法标识符包括：

```text
TwoStageArc
TwinSlash
NullRing
RadiusUp
E.CooldownDown
```

- [ ] 控制台命令成功时，构筑被写入当前局 `BuildHistory`，而不是只临时显示奖励卡。
- [ ] 若命令在奖励反馈期间被拒绝，等待当前反馈关闭后再执行，不把该次拒绝当作 HUD 缺陷。
- [ ] 超过五项的滚动测试应使用同一分类中至少六个合法且已获得的构筑；若测试数据采用“最后索引”语义 `count = 6`，按第 5 节的七项示例验收。

## 4. 常驻构筑 HUD

### 4.1 数据与生命周期

- [ ] 无构筑历史时，右下角常驻构筑 HUD 隐藏，不显示未获得构筑占位。
- [ ] 获得第一项构筑后，HUD 出现；最近构筑较大，上一构筑槽位隐藏。
- [ ] 获得第二项构筑后，最近构筑保持大尺寸，上一构筑以较小尺寸显示。
- [ ] 后续获得构筑时只更新最近/上一条，不重复创建 HUD，不重复绑定事件。
- [ ] HUD 显示内容来自当前局已获得的 `BuildHistory`，不显示目录中尚未获得的构筑。
- [ ] 重新进入房间或恢复运行时数据后，最近/上一构筑和 Icon 仍与运行时数据一致。

### 4.2 常驻 HUD 视觉

- [ ] 面板位于战斗画面右下角的安全区内，不遮挡小地图、技能槽和主要战斗区域。
- [ ] 最近构筑层级顺序为：面板 → 飞白 → 墨蓝 → Icon；B 键帽和文字位于提示区域。
- [ ] 墨蓝层只强调最近构筑，不烘焙进 Icon，不出现黑色矩形背景。
- [ ] B 键提示底图不烘焙字母；键位文字由运行时文本绘制。
- [ ] 新构筑出现时只产生一次反馈，不因事件重复触发而闪烁或叠加动画。

## 5. 详细 HUD 五槽位和箭头

对每个有构筑的分类分别检查，分类之间的窗口起点互不影响。

### 5.1 槽位和顺序

- [ ] 只显示当前局已获得的构筑；未获得项不占用槽位，不留下空洞。
- [ ] 已获得构筑按 `build-list.md` 的 BuildId/SortOrder 顺序连续排列。
- [ ] 分类数量 `<= 5` 时，五个槽位规则成立，两侧箭头均隐藏，不保留空白按钮占位。
- [ ] Icon 缺失时只在对应槽位显示几何占位，其他槽位、文字和箭头不消失。
- [ ] Icon 使用对应的 `_Redrawn` 资源；`InkGrenade` 的图形仍表现范围攻击，不使用炸弹意象。

### 5.2 用户确认的超五项窗口

当测试数据的分类索引范围为 `0..6` 时，必须依次能够得到以下三种状态：

```text
StartIndex = 0  →  0,1,2,3,4,>
StartIndex = 1  →  <,1,2,3,4,5,>
StartIndex = 2  →  <,2,3,4,5,6
```

- [ ] 初始窗口只显示右侧 `>`，左侧 `<` 隐藏。
- [ ] 点击 `>` 后窗口向后移动一格，`<` 出现；最后一页隐藏 `>`。
- [ ] 点击 `<` 后窗口向前移动一格，回到初始窗口时隐藏 `<`。
- [ ] 箭头无框、无底板、无黑色矩形，不被误认为 Build Icon。
- [ ] 箭头始终位于左页对应分类行内，不能越过书页中缝进入右页。

### 5.3 键盘、鼠标和焦点

- [ ] 打开详细 HUD 后，焦点落到第一个可用构筑槽位。
- [ ] 鼠标悬停或点击 Icon 会更新同一份选中状态，右页预览、标题和描述同步变化。
- [ ] 选中状态使用独立圆形墨蓝层，中心填充；不出现默认 Button 的蓝色矩形。
- [ ] 当前选中 Icon 位于窗口最后一位时按 `D`，效果等同于点击 `>`。
- [ ] 当前选中 Icon 位于窗口第一位时按 `A`，效果等同于点击 `<`。
- [ ] 普通左右输入只移动当前可见槽位；到边界时才滚动窗口，不越界、不跳过已获得项。
- [ ] 上下输入在分类之间移动时跳过空分类，焦点不落到隐藏箭头。
- [ ] 鼠标可以点击箭头；箭头命中区透明且不会绘制按钮边框。

## 6. B 键详细 HUD 与 scrim

### 6.1 打开和关闭

- [ ] 在战斗中按配置的 B 键打开详细构筑 HUD；有无构筑历史都不应创建重复实例。
- [ ] 打开后游戏暂停，输入模式切换为 UI Only，鼠标可见，焦点交给首个可用槽位。
- [ ] 打开后详细 HUD 的独立 Widget 层级高于常驻 HUD，奖励/商店模态已经打开时不叠加第二个模态。
- [ ] 按 B 或 `Escape` 关闭详细 HUD。
- [ ] 关闭后恢复打开前的暂停所有权、输入模式、鼠标状态、移动/视角输入和焦点。
- [ ] 反复打开/关闭至少三次，不出现重复面板、重复事件刷新或输入吞键。

### 6.2 Scrim 视觉和交互

- [ ] 详细 HUD 打开时，scrim 覆盖全屏战斗背景，位于书页之后、常驻 HUD 之前。
- [ ] scrim 为半透明深色薄幕，只降低场景权重；不生成黑色矩形边缘，不覆盖书页内容。
- [ ] 书页、Icon、文字、箭头仍清晰可操作；scrim 不抢占槽位和箭头点击。
- [ ] 关闭详细 HUD 后 scrim 完全消失，战斗画面恢复原始亮度。
- [ ] scrim 的 `ScrimColor` 可在 `UCombatBuildDetailsWidget`/对应蓝图中调整；调整 alpha 不改变 panel 或 Icon 资源。

## 7. Panel、选中态与排版

- [ ] 新 panel 使用独立透明 PNG 和 `.uasset`，不把文字、Icon、B 字符或选中态烘焙进背景。
- [ ] panel 四角和外部区域保持真实透明；不出现白色矩形边、棋盘格或深色底板。
- [ ] 纸张边缘的自然纸白属于 panel 本体纹理可以保留，但不能形成额外的白色 halo/描边。
- [ ] 五条左页分隔线分别对应五个分类内容带，Icon、文字和箭头不压线、不跨中缝。
- [ ] 左侧分类文字整体位于左页内容安全区内；`左键近战`、`右键弹幕` 等标签不被错误拆行。
- [ ] 右页标题和 description 在右页内容区内自动换行，不越过书页中缝或右侧边缘。
- [ ] 文字使用已导入的 `AaGuDianKeBenSongYouMoBan_2` UE 字体；字号、行距和换行在目标分辨率下可读。
- [ ] 选中蓝墨层与 Icon 分离：移除蓝墨层后 Icon 仍保持黑白轮廓；移除 Icon 后蓝墨层不出现黑白形状。
- [ ] 选中态中心没有不应存在的透明洞，且不会扩大为实心蓝色矩形。

## 8. 分辨率和安全区

在每个分辨率至少复核一次常驻 HUD和详细 HUD；记录实际窗口尺寸，不把被编辑器限制的窗口尺寸误记为通过。

- [ ] `1280 × 720`：常驻 HUD 位于右下安全区；详细面板居中、无裁切。
- [ ] `1920 × 1080`：左右页、五行分类、右页预览和 scrim 比例保持一致。
- [ ] 宽屏窗口（目标 `2560 × 1080` 或可用的等比例宽屏窗口）：面板不被拉伸、裁切或推入屏幕外。
- [ ] 编辑器嵌入 PIE 与 Standalone PIE 至少各测一次；两种模式下整体锚点和安全区均正确。
- [ ] 调整窗口大小后重新打开详细 HUD，panel、文字和 scrim 不出现旧尺寸残留。

## 9. 运行日志与证据

### 9.1 重点日志

检查 PIE 日志中至少出现以下生命周期/刷新事件：

- `Combat build HUD created`
- `Combat build HUD bound`
- `Combat build HUD subscribed to build-history changes`
- `Combat build HUD received build-history change`
- `Combat build HUD history refreshed`
- `Combat build details HUD opened`
- `Combat build details HUD closed`

如出现 `Combat build HUD asset unavailable`，先检查 UE 对象路径、同名 `.uasset` 和编辑器导入状态，再判定视觉问题。

### 9.2 必留证据

- [ ] 无构筑历史的常驻 HUD 截图。
- [ ] 已获得一项和两项构筑的常驻 HUD 截图。
- [ ] 详细 HUD 打开时包含 scrim 的截图。
- [ ] 详细 HUD 的 `0..4,>`、中间页和末页截图。
- [ ] 选中态圆形墨蓝层截图，确认没有蓝色矩形。
- [ ] `1280×720`、`1920×1080` 和宽屏窗口截图。
- [ ] B/Escape 关闭后恢复战斗输入的日志或视频证据。
